Singify

SingStar, but the song library is Spotify.

Spicetify extension · Bun + TypeScript · Linux · source on GitHub

Singify is a free, open-source Spicetify extension that turns Spotify into a karaoke machine. When a song starts playing it finds the matching UltraStar chart, downloads it, and drops a fullscreen overlay on top of the Spotify client: lyrics scrolling with a per-syllable wipe, a pitch highway showing the note you're supposed to be hitting, and a live score off your microphone. Solo, or one to four players head-to-head with a mic each.

Before you install

It needs a helper process running. Spotify's renderer has no filesystem of its own, so chart download and the song cache live in a small local server you start yourself (bun run helper). Without it there is nothing to sing — not even a song you've already cached. The Spicetify Marketplace can only install the overlay, not the helper.

Built and tested on Linux only. Nothing in it is deliberately Linux-bound — Bun and Spicetify both run on macOS and Windows — but it has never been run there, config lands in XDG paths rather than the platform-native ones, and the documented deploy route is spicetify-nix on NixOS.

What it does

  • Automatic charts. Songs are matched against USDB and the UltraStar .txt is fetched and cached on first play — no manual hunting for files.
  • Pitch scoring off your mic. Octave-agnostic, so it doesn't punish you for singing an octave down. Beat-weighted 9000 points plus a 1000-point line bonus, golden notes worth double, matching UltraStar's scoring rules.
  • One to four players. Each gets a coloured lane, their own microphone device, gain and noise gate, and their own running score.
  • Sessions. Pick a Spotify playlist, a difficulty (±2 / ±1 / ±0 semitones) and a round count; it runs the rounds and produces an aggregate result screen.
  • Competitive mode. One microphone, same song, take turns — for when you only own one mic.
  • Per-song sync offset. Nudge the chart against the audio and it remembers it for that track.

The problem it actually solves

The existing karaoke engines are good. USDX, Vocaluxe, Performous, UltraStar Play, allkaraoke — and USDB, the community chart database all of them lean on, is the reason any of this is possible. They solved singing a long time ago.

What none of them solved is getting to the singing. Every one needs a chart and the matching audio file, at the matching length, for every song anybody might want. Someone names a song at a party and you're in a file manager.

Singify skips that step. The audio is whatever Spotify is already playing, so the library is Spotify's entire catalogue; the chart resolves itself in the background while the song starts. You name a song, it's on.

Why it isn't a fork of one of them

Those engines own the audio — each decodes the file itself, so it knows exactly where the playhead is and can analyse the backing track. Spotify never hands out decoded PCM; that's what the DRM is for.

So Singify rides only what Spotify does expose: the playback clock and your microphone. The chart is overlaid on whatever is already playing, and the clock is interpolated from Spotify's own player events. That constraint is the whole design — and it's also what makes the library problem disappear.

How it's built

The karaoke rendering is developed in a plain browser harness with instant reload, and the identical component then runs unchanged inside Spotify. That works because of a small ports-and-adapters split: a shared core that takes the playback position as a prop and has no idea which world it's in, and two host adapters that fill the holes — one faking the Spicetify global with a synthetic transport clock, one using Spotify's injected React and its real player events. Add a feature once and both hosts get it. Every screenshot above was captured from the browser harness.

A small localhost helper (Bun) handles the parts a browser renderer can't: the USDB login, the chart download, and the on-disk cache. Spotify's content-security policy does permit the renderer to fetch 127.0.0.1, so no CSP patching is required.

The pitch highway is DOM and CSS transforms rather than canvas — a single GPU-composited translateX moves the whole note track. On the RDNA4 GPU this was built on, that's both the cheaper and the less crash-prone path.

What you need

  • Spotify with Spicetify
  • Bun, to build the extension and run the helper
  • A microphone (one per player, if you want versus mode)
  • A free USDB account for automatic chart download

Built and run on Linux (NixOS, deployed declaratively through spicetify-nix). Install instructions and the current module-by-module status are in the README on GitHub.

Status

It runs live in a real Spotify client. Microphone scoring, the lyric scroll, USDB auto-resolve, multi-round sessions and the localhost helper all work end to end. The parser, USDB client, cache, resolver and scoring are covered by tests.
